# Slack Onboarding Wizard

## 0. 준비

교수 로그인(이메일 OTP). Slack 워크스페이스 생성/관리 권한을 가진 담당자의 협조가 필요할 수 있다. 앱이 임의로 완전한 워크스페이스를 자동 생성할 수 있다고 가정하지 않는다.

## 1. 연결

Slack OAuth로 앱 설치. bot/user scope는 기능별 최소권한 기준으로 실제 Slack 공식 문서를 확인해 선정한다. `team_id`, 설치 사용자, bot token, 설치 시각 기록.

## 2. 공식 채널 템플릿

교수가 팀 이름을 넣으면 `teamplanet-{class}-{team}` 채널을 생성하거나, 기존 채널을 공식 프로젝트 채널로 지정한다. 봇을 채널에 초대하고 읽기 권한을 검증한다.

## 3. 참가자 초대와 고지

교수/운영자가 학생을 해당 팀 채널에 초대. **채널 활성화 전** 정확한 분석 기간, 모든 메시지/스레드/이미지 범위, 모델 외부 전송, 교수에게 보이는 결과 및 이의제기 경로를 고지한다.

## 4. 동의 게이트

전체 수집은 학생별 선택권·대체 평가와 충돌할 수 있다. 비동의자가 같은 채널에 있는 경우 그 학생 메시지를 마음대로 처리해서는 안 된다. **동의 정책과 대체 방식을 확정하기 전에는 채널 수집을 활성화하지 않는다.** 동의 철회 시의 데이터 처리도 사전 명시.

## 5. 수집 시작

동의와 bot 권한 검증 후 채널 수집 상태를 `active`로 변경. Slack Events API와 History/replies API를 조합할 경우 이벤트 누락·수정·삭제·스레드 재조회 기준을 정의한다. 파일/이미지는 접근 권한과 수집 근거를 별도로 확인.

## 6. 교수 분석 실행

팀과 기간 선택 → 수집 범위 프리뷰 → 실행 → 진행 상태 → 4역량 평가 카드 → 근거 검토 → 확정.

## 비목표

사적 DM 수집, 사전 동의 전 백필, 비공식 채널 전체 읽기, 모든 학생이 새로운 작업 도구를 사용하게 강제.
