# Slack Onboarding Wizard

파일럿 정책은 [PRIVACY_AND_DATA.md](PRIVACY_AND_DATA.md)와 [ADR-0002](ADR/0002-pilot-policy.md)를 따른다. 성인 4명×20팀, 약 2개월의 내부 실험이며 교수 참고/피드백·제품 검증용이다. 학생 QR 재확인과 본인 문의 페이지는 포함하고 학생 평가 열람 포털은 만들지 않는다.

## 0. 준비

교수 로그인(이메일 OTP), 수업 시작·종료일·담당 교수 이메일·웹 문의 기한 n일을 설정한다. Slack 워크스페이스 생성/관리 권한을 가진 담당자의 협조가 필요할 수 있다. 앱이 워크스페이스를 자동 생성할 수 있다고 가정하지 않는다.

## 1. 연결

Slack OAuth로 앱 설치. bot/user scope는 기능별 최소권한 기준으로 실제 Slack 공식 문서를 확인해 선정한다. `team_id`, 설치 사용자, bot token, 설치 시각 기록.

#6 구현: bot scope 6개(user scope 없음)와 상태 값은 [API_CONTRACT.md](API_CONTRACT.md)의 "Slack 설치·연결", 앱 생성·secret은 [DEPLOYMENT.md](DEPLOYMENT.md)의 "Slack 앱"을 따른다. 실험 workspace 연결 확인 절차:

1. Slack 관리 권한이 있는 담당자와 함께 교수 계정으로 로그인하고 `/v1/slack/install`로 이동한다. Slack 동의 화면에서 workspace 이름과 권한 목록을 확인하고 허용한다.
2. `/workspace?slack=installed`(재설치면 `reinstalled`)로 돌아오는지 확인한다. 다른 값이면 원인을 해결한다. `workspace_mismatch`는 이미 다른 workspace가 연결된 상태라 자동 교체하지 않는다.
3. `GET /v1/slack/connection`이 `connected`, 올바른 workspace 이름, 빈 `missingScopes`를 반환하는지 확인한다. 응답에 `xoxb-` 토큰이 없어야 한다.
4. bot membership: 시험용 공개 채널에서 `/invite @TeamPlanet`을 실행하고 채널 정보의 통합(Integrations)에 앱이 보이는지 확인한다. API로 채널 멤버십을 확인하는 기능은 #7에서 추가한다. 이 단계에서 메시지 조회나 백필을 하지 않는다.
5. 철회 확인: Slack 앱 관리에서 앱을 제거한 뒤 `connection`이 `revoked`가 되는지, 다시 설치하면 `connected`로 돌아오는지 확인한다.

## 2. 공식 채널 템플릿

교수가 팀 이름을 넣으면 `teamplanet-{class}-{team}` 채널을 생성하거나, 기존 채널을 공식 프로젝트 채널로 지정한다. 봇을 채널에 초대하고 읽기 권한을 검증한다.

#7 구현: `POST /v1/teams`가 채널 생성·지정과 봇 참여를 하고, `GET /v1/teams/:teamId/membership`이 봇·학생의 채널 멤버십을 Slack에서 직접 확인한다. 규칙은 [API_CONTRACT.md](API_CONTRACT.md)의 "채널·멤버 구현"을 따른다.

## 3. 참가자 초대와 고지

교수가 오프라인 동의서를 배포·확보하고 동의한 학생만 Slack에 초대한다. 학생은 QR로 서비스 페이지에 진입해 같은 서류 동의를 체크박스로 재확인한 후 다음 단계로 간다. 서버는 수업·학생·Slack 계정·서류 버전과 교수의 증빙 참조를 연결하고 공개 QR/임의 ID로 다른 학생의 동의를 바꿀 수 없게 한다. 종이 원본은 교수가 관리하며 기본 스캔 업로드는 요구하지 않는다.

QR 진입 시 수업 초대/학생 본인을 확인하고 Slack 계정 매핑은 초대·가입 후 활성화 전에 확정한다. Slack 가입 전 재확인 단계에 기존 workspace 멤버십을 요구하는 순환 조건을 만들지 않는다.

고지에는 허용 기간·대화/스레드/이미지의 실행 중 처리·외부 모델 전송·서비스의 링크/요약 중심 보관·수업 종료 후 3개월 삭제·교수 검토·문의/철회/정정 경로를 포함한다. ADR-0003의 이름/이미지 전송·Qwen/DeepInfra ZDR 결정을 반영하고 실제 처리 조건과 고지의 일치는 시작 전에 확인한다.

## 4. 동의 게이트

파일럿은 전원 사전 동의·고정 참가자/고지문을 전제로 한다. 비동의자 대체 평가·중도 가입·정책 개정용 전용 화면은 구현하지 않고 교수 안내를 제공한다. 서버의 동의/멤버십/권한 확인은 유지한다. 누락·철회·미확인 참가자·정책 변경·봇 권한 상실이 발견되면 해당 채널과 관련 작업을 중지하고 교수/운영자 확인을 요구한다. 초대·QR 접속·교수의 우회 플래그로 자동 granted 처리하지 않는다.

## 5. 수집 시작

오프라인 확인·학생 QR 재확인·실제 참가자·수업 종료일·모델 전송 고지·bot 권한 검증 후 `active`로 변경한다. 활성화 이후 허용 구간만 처리하며 동의 전/비활성 구간은 백필하지 않는다. 과거 스레드도 허용 구간 밖 원문을 끌어오지 않고 문맥 부족을 표시한다.

Events로 변경/삭제 metadata를 보정하고 분석 시 History/Replies로 기간 전체를 재조회한다. 원문/이미지는 실행 중 메모리에서만 처리하고 DB/Queue/로그에는 링크·참조·지문·요약을 남긴다. 원문이 없는 부분을 복원했다고 주장하지 않는다.

## 6. 교수 분석 실행

팀과 기간 선택 → 수집 범위 프리뷰 → 실행 → 진행 상태 → 초기 교수 선택 역량의 평가 카드 → 근거 검토 → 확정.

열람·확정·출력 전에 현재 원문과 요약을 재검증한다. 수정·삭제·불일치 링크는 제외하고 관련 초안/교수 확정본을 무효화·재검토한다. 요약 수정은 새 버전으로 남긴다. Slack 장애/권한 실패는 삭제와 구분하고 검증 불가 상태에서 확정·출력하지 않는다.

학생 문의는 담당 교수 이메일과 웹에서 받는다. 웹 문의는 접수 후 교수 설정 n일에 답변 여부와 무관하게 자동 삭제하고 제출 전에 기한을 보여준다. 학생 본인 피드백 요청에는 교수가 검증된 리포트를 출력해 타인 정보가 노출되지 않는지 확인한 뒤 전달한다. 요약·리포트는 수업 종료 후 3개월에 삭제하며, 철회/원문 변경 시 사용 중지·무효화는 즉시 적용한다.

## 비목표

사적 DM 수집, 사전 동의 전 백필, 비공식 채널 전체 읽기, 모든 학생이 새로운 작업 도구를 사용하게 강제.
