# 학생 개인 QR 재확인 — #29

## 경로와 신원 경계

교수 설정 화면에서 같은 수업 학생의 오프라인 동의서 확보·증빙 참조를 먼저 기록한다. 이때 Slack 가입·매핑을 요구하지 않는다. 교수가 수업 초대와 학생 본인을 확인하고 해당 학생에게만 개인 QR/링크를 전달한다. 기존 API의 개인별 43자 난수 토큰이 제한된 학생 인증 수단이며, 공개된 공통 QR이나 학생 ID·체크값만으로 재확인할 수 없다.

이 방식은 별도 학생 로그인/OTP를 제공하지 않는다. 개인 링크가 유출되면 소지자가 사용할 수 있으므로 단체 채널에 게시하지 않고 본인에게 직접 전달해야 한다. 서버에는 토큰 해시만 저장한다. QR은 브라우저의 `qrcode-generator`로 생성하며 외부 QR 서비스로 전송하지 않는다. 링크는 기존 7일 만료 계약을 따른다. 재발급하면 이전 미사용 링크는 무효다.

학생 경로는 `/consent/confirm#<token>`이다. 토큰은 fragment와 요청 본문에만 있고 query/path·로그·localStorage/sessionStorage에 저장하지 않는다. 페이지는 `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `noindex,nofollow`를 설정한다. 학생 API 요청은 `credentials: omit`이므로 교수 쿠키를 사용하거나 발급하지 않는다. 학생 페이지에는 교수 워크스페이스나 타인의 결과로 가는 기능이 없다.

## 안내와 상태

유효한 개인 링크로만 수업·팀·학생 표시명·서류 버전·담당 교수 이메일을 조회한다. 학생은 대상과 서류 버전을 확인하고 오프라인 서류 동의 체크 후 제출한다. 화면은 공식 공개 채널/DM 제외, 원문·이미지 실행 중 처리, 실제 표시명·프로젝트 이미지의 Qwen/DeepInfra ZDR 전송, 보관·3개월 삭제, 교수 검토, 문의·철회 경로를 고지한다. 실제 처리 조건·지역과 오프라인 고지가 다르거나 불명확하면 제출하지 않고 교수에게 문의한다.

서버 확인 뒤 현재 상태를 다시 조회해야 성공으로 표시한다. 새로고침은 fragment의 같은 개인 링크로 조회만 수행하며 재동의를 자동 제출하지 않는다. 현재 grant의 중복 제출은 같은 확인 시각을 반환하고 동의 이력을 중복 작성하지 않는다. 미체크·잘못된 링크·만료·철회·버전 변경·수업 종료·네트워크 실패는 제출/진행을 막고 복구를 안내한다. 동의 확인만으로 수집이 활성화되지는 않는다.

## 동의 이력과 수집 보호

Migration `0011_cynical_vapor.sql`은 `consent_confirmations.consent_history_id` nullable FK만 추가하며 기존 SQL·행·트리거를 삭제하지 않는다. 새 링크는 발급 대상 grant의 정확한 history ID에 연결한다. 같은 밀리초의 철회→재동의도 이전 링크를 재사용할 수 없다. 조회·확인·재사용·수집 guard는 현재 grant/버전/정책과 이력 일치를 검증한다.

이전 링크의 NULL history ID는 추정해 채우지 않는다. 개인정보·동의 이력을 보존하면서 해당 링크를 거부하므로 교수의 재발급과 학생 재확인이 필요하다. 현재 grant로 확인된 링크만 제한된 중복 조회/제출을 허용한다. 원래 링크 만료는 이미 완료된 동의를 7일 뒤 취소하는 의미가 아니며 철회·정책 변경·수업 종료는 별도로 차단한다.

Slack 가입 전 참가자는 동의 기록으로 팀에 연결한다. 이 참가자도 활성화 전 Slack 계정/실제 채널 참여를 완료해야 한다. 미매핑 동의 참가자가 있으면 활성화 쓰기 안과 공통 collection guard 모두 차단한다. 새 미매핑 참가자의 동의 기록은 활성 팀을 중지한다. 교수가 다른 수업 학생을 연결하는 요청은 거부한다.
