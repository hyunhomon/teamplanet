# 파일럿 운영 정책과 데이터 수명주기

서비스 운영자가 2026-10-27 승인한 #5의 제품 정책이다. [ADR-0002](ADR/0002-pilot-policy.md)에 승인 근거를 기록한다. 교수의 루브릭 승인·학교의 별도 승인·외부 제공자의 처리 조건을 확인했다는 의미는 아니다.

## 목적과 책임

- 대학 대상 서비스의 성인 내부 실험: 4명 × 20팀, 약 2개월. 실제 시작·종료일은 수업별로 기록한다.
- 교수 참고·피드백과 제품 검증에만 사용한다. 파일럿에서 실제 성적 반영·자동 성적 확정·학생 공개 순위는 하지 않는다. 논문·연구 목적의 재사용은 이번 승인에 포함하지 않는다.
- 운영자 `hyunhomon`은 서비스 정책·접근·보관·삭제 운영을 담당한다. 교수는 루브릭과 근거의 해석·검토·교육적 판단을 담당한다. 서비스 자료는 근거와 검토 후보이며 교수의 결정과 구분한다. #15의 평가 기준 승인을 운영자 승인으로 대신하지 않는다.

## 오프라인 동의와 QR 재확인

교수가 고정 버전 동의서를 오프라인으로 배포·확보하고 동의한 학생만 Slack에 초대한다. 학생은 QR로 서비스 페이지에 진입해 해당 서류에 동의했음을 체크박스로 재확인한 뒤 다음 단계로 간다.

교수의 오프라인 확보 확인과 학생의 재확인을 수업·학생·Slack 계정·서류 버전에 연결한다. 공개 QR을 열거나 임의 student ID/체크값을 전송하는 것만으로 동의할 수 없다. #8/#9에서 학생 식별·초대 확인과 증빙 참조를 정의한다. 종이 원본은 교수가 관리하며 서비스에 종이 스캔본을 기본 업로드하지 않는다.

QR 단계에서는 수업 초대와 학생 본인을 확인하고, Slack 계정 매핑은 초대·가입 후 활성화 전에 최종 검증할 수 있다. 아직 Slack에 가입하지 않은 학생에게 기존 workspace 멤버십을 QR 진입 조건으로 요구해 가입을 막지 않는다. 학생 재확인이 참가자 매핑·수집 활성화를 자동 완료하는 것은 아니다.

전원 사전 동의·참가자 고정·고지문 고정을 파일럿 전제로 한다. 비동의자 대체 평가·중도 가입·동의서 개정용 전용 UI는 구현하지 않고 교수에게 동의 관리·대체 평가에 관한 안내를 제공한다. 이 전제는 서버 gate를 제거하는 우회 플래그가 아니다. 동의 누락·알 수 없는 참가자·철회·정책 변경·권한 상실이 발견되면 해당 채널/관련 작업을 차단하고 교수·운영자 확인 대상으로 돌린다. 일반 해결 흐름은 파일럿 이후 범위다.

승인된 공식 채널의 활성화 이후 허용 구간만 처리한다. 동의 전/비활성 구간의 대화를 백필하지 않는다. 이전 스레드의 새 답글을 읽어도 허용 구간 밖 원문을 분석에 끌어오지 않고 문맥 부족을 한계로 표시한다.

## 원문 비보관과 근거 저장

Slack을 원문 저장소로 사용하고 TeamPlanet에는 다음을 보관한다.

- 내부 근거 ID, workspace/channel/message/thread 식별자와 메시지 링크 세트
- 허용 구간, 원문 revision/수정·삭제 상태/내용 지문, 마지막 검증 시각
- 요약·근거·반례·한계·사람 검토 필요 정보·교수 검토 상태·버전
- 동의 확인·접근·변경·무효화·만료 이력과 학생 문의

대화 본문 전체·이미지 원본·전체 Events/History payload를 D1·KV·R2·Queue·DLQ·로그·영구 체크포인트에 복제하지 않는다. 요약을 원문 전체의 우회 사본으로 만들지 않는다. 링크·요약·지문도 학생 관련 자료이며 접근·보관·무효화 대상이다.

분석 시 허용 기간 전체를 Slack에서 페이지/스레드 단위로 조회하고 원문·이미지는 필요한 실행 중 메모리에서만 처리한다. 재시작 시 참조로 재조회하고 revision을 확인한다. 요약만으로 전체 대화를 분석했다고 주장하지 않는다. Slack에서 사라진 대화는 복원할 수 없으므로 누락 범위와 한계를 표시한다.

원문 비보관이 원문의 외부 전송 금지를 뜻하지 않는다. 실행 중 Cloudflare/OpenRouter/선택 모델이 처리하는 범위는 고지에 포함한다. 식별자·이미지의 가림 수준, 모델별 보관·학습 사용·처리 지역과 고지의 일치는 #15 및 파일럿 시작 전에 확인한다. 사용자 답변 10은 저장 전략을 정했으며 이 전송 세부 사항까지 승인했다고 추정하지 않는다.

기존 `messages.text` 등 초안 컬럼은 원문 보관 허용을 의미하지 않는다. #11/#12/#13/#16에서 참조·요약 방식의 Drizzle schema와 신규 migration을 설계한다. 이 문서 PR은 기존 컬럼·평가 자료·동의 이력 트리거를 삭제하지 않는다.

## 리포트 재검증과 무효화

열람·확정·출력 전에 내부 파이프라인으로 현재 Slack 원문과 revision/내용 지문 및 요약의 정합성을 대조한다. 링크 접속 성공만으로 요약을 신뢰하지 않는다. Events 변경/삭제 통지는 조기 무효화에, 조회 시 재검증은 누락 보정에 사용한다.

원문 수정·삭제 또는 요약 불일치가 확인되면 해당 링크를 유효 근거 세트에서 제외한다. 영향받은 요약·분석 초안·교수 확정본을 모두 무효화하고 재분석·재검토 대상으로 둔다. 허용된 현재 원문으로 만든 새 요약은 새 버전이며 교수 검토를 다시 받는다. 링크만 지우고 기존 판단을 그대로 유지하지 않는다. 원문이 없으면 근거 부족을 표시한다.

Slack 인증/권한 오류·rate limit·일시 장애는 삭제 증거가 아니다. 검증 불가/재시도를 구분하고 최신 검증 완료로 확정·출력하지 않는다. 오래된 캐시/체크포인트로 차단을 우회하지 않는다. 이미 전달한 종이/파일은 자동 회수할 수 없으므로 이전 버전의 정정·재전달 필요를 교수에게 표시한다.

## 보관과 물리 삭제

사용 중지·무효화와 물리 삭제의 시점을 구분한다. 철회 확인 시 새 수집·모델 전송·관련 작업을 중지하고 관련 결과의 일반 열람·확정·출력을 막는다. 교수 확정본도 무효화·재검토한다. 재분석은 철회된 자료의 재수집 허용을 뜻하지 않으며 허용된 남은 자료만 사용한다.

| 자료 | 보관 종료와 삭제 기준 |
|---|---|
| 원문 대화·이미지·전체 API payload | 영구 보관하지 않음; 필요한 실행 중에만 처리 |
| 링크·요약·근거·초안·교수 확정 리포트 | 수업 종료일부터 3개월 후 삭제; 무효화된 버전도 동일 기한 적용 |
| 동의 확인·증빙 참조·관련 감사/작업 이력 | 수업 종료일부터 3개월; 일반 상태 변경 시 이력 보존, 만료 정리는 통제된 별도 경로 |
| 학생 웹 문의·답변 | 접수 시각부터 교수 설정 n일 후 자동 삭제; 수업 종료 기준과 구분 |

3개월을 90일로 치환하지 않는다. 수업 종료일을 활성화 전에 등록하며 만료 후 조회·전송·출력을 막고 연결된 파생 자료를 정리한다. 문의의 n은 교수가 설정하는 답변 기한이자 접수 후 보관기간이다. 답변 여부와 관계없이 접수 시각+n일에 삭제하고, 제출 전에 기한을 표시한다. 응답을 달았다고 접수 시각을 초기화하지 않는다. 설정 변경이 기존 문의 기한을 몰래 연장하거나 즉시 삭제시키지 않도록 문의별 적용 기한을 보존한다. 기본 n을 임의로 정하지 않는다.

웹 문의는 저장 성공 후 접수 표시를 제공한다. 삭제 작업은 처리 중/완료/실패를 추적하며 미실행 작업을 완료로 표시하지 않는다. 별도 답변 독촉 기능은 이번 요구에 포함하지 않는다. 요약·리포트의 자동 보관 종료와 별개의 조기 삭제 요청 운영은 담당 교수/운영자에게 전달하며, 3개월 정책을 모든 별도 삭제 요청의 거절 근거로 사용하지 않는다.

`consent_history`는 정상 동의 변경에서 append-only로 보존한다. 만료 정리는 #14에서 권한·감사·연관 참조를 확인하는 별도 경로로 구현하며 감사 이력이라는 이유로 무기한 보관하지 않는다. 종이 원본/출력물·Slack·외부 제공자 복사본은 서비스 DB 삭제가 자동 삭제하지 않으므로 관리 경계를 고지한다. 제공자 백업·삭제 기능과 복구 시 만료/철회 상태 재적용은 파일럿 시작 전에 확인하며 임의의 예외 보관기간을 추가하지 않는다.

## 접근·문의·학생 전달

- 교수는 자기 수업·팀만 열람한다. 개발·운영자의 원문 접근은 기본 금지하며 승인된 장애 조사 접근의 범위·사유·시각을 기록한다.
- 학생 문의·철회·정정은 담당 교수 이메일 또는 웹 문의 기록으로 받는다. 웹 문의의 교수 설정 n일 자동 삭제는 외부 이메일함 삭제까지 보장하지 않는다.
- 학생 페이지는 QR 재확인·본인 문의에 한정한다. 교수 대시보드·타인 문의/평가에 접근할 수 없고 공개 링크만으로 학생 신원을 위조할 수 없다.
- 학생이 본인 평가 조회를 요청하면 교수가 최신 검증된 리포트를 출력해 전달한다. 전체 대화·타 학생 개별 평가는 출력하지 않고 교수에게 타인 정보 확인을 요구한다. 근거·한계·검증/버전 시각·교수 확인 상태를 구분한다. 학생 평가 열람 포털은 범위 밖이다.

## 상태별 처리 기준

| 상태/사건 | 수집·전송 | 결과·후속 처리 |
|---|---|---|
| 정책/모델 전송 고지·수업 종료일 미확인 | 금지 | 합성 개발 자료만 사용, 시작 전 확인 |
| 오프라인 확인·QR 재확인 누락 | 금지 | 교수 확인; 자동 granted 금지 |
| 전원 확인·계정/멤버십·권한 확인 후 활성화 | 허용 구간만 처리 | 기간 전체 조회, 현재 근거 검증 후 제공 |
| 미확인 참가자·철회·정책 변경·권한 상실 발견 | 해당 채널/관련 작업 중지 | 일반 해결 UI 없이 교수·운영자 확인 |
| 원문 수정·삭제·요약 불일치 확인 | 해당 revision 사용 금지 | 링크 제외·초안/확정본 무효화·새 버전 재검토 |
| Slack 장애/권한 문제로 재검증 불가 | 검증/전송 보류 | 삭제와 구분, 확정·출력 보류 |
| 철회 확인 | 새 수집·전송 중지 | 확정본 포함 무효화, 3개월 보관 후 물리 삭제 |
| 수업 종료 후 3개월 만료 | 금지 | 링크·요약·결과·연결 이력 삭제 |
| 웹 문의 접수 후 n일 만료 | 해당 문의 사용 금지 | 답변 여부와 무관하게 문의·답변 자동 삭제 |

#24는 합성 자료로 동의 대상 바꿔치기·미확인 활성화·변경/삭제·Slack 장애·확정본 무효화·철회 후 재전달·3개월 만료·문의 n일 경계·문의 권한·출력물 검증을 확인한다. 실제 수집 시작은 문서 병합만으로 허용되지 않으며 #15의 모델/전송 고지 확인과 #25의 파일럿 시작 검토를 충족해야 한다.

재조회/삭제 이벤트 근거: [conversations.history](https://docs.slack.dev/reference/methods/conversations.history/), [message_deleted](https://docs.slack.dev/reference/events/message/message_deleted/). 조회 권한·원문 존재 여부를 검증 없이 추정하지 않는다.
