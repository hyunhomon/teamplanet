# Privacy, Consent, and Data Lifecycle

이 문서는 제품 운영 원칙의 초안이며 법률 자문 또는 한국 개인정보보호법 적법성 인증이 아니다.

## 데이터 범위

- In scope: 명시적으로 지정된 팀별 프로젝트 채널에 수집 활성화 이후 존재하는 메시지, 스레드, 합의된 이미지·파일 참조, 메시지 메타데이터.
- Out of scope: DM, 다른 채널, 개인 프로필의 불필요한 속성, 수업과 무관한 개인 정보.
- Model processing: OpenRouter를 통한 외부 모델 제공자 전송 범위·보관 정책을 고지해야 한다.

## 동의 요건

목적, 항목, 보유 기간, 제3자/국외 이전 여부, 거부 가능성 및 성적상 불이익 방지, 열람·정정·삭제 요청 경로를 구체화한다. 수업 관계의 힘의 불균형 때문에 동의가 실질적으로 자발적인지 검토한다. 비동의 학생에 대한 대체 평가 방법은 운영 전 필수 확정.

## 권한

- Professor: 자기 수업·팀의 요약/평가/필요한 근거만 조회
- Operator: 연결·삭제 등 운영 수행, 원문 내용 최소 접근
- Student: 자신의 동의/수집 상태, 본인 피드백 및 정정 요청 접근 (출시 범위 결정)

## 보관·삭제

`consents`는 학생별 최신 동의 상태를 보관하고, `consent_history`는 동의·철회·재동의 당시의 상태, 동의서 버전, 기록 시각을 각각 보존한다. SQL 마이그레이션의 INSERT/UPDATE 트리거가 현재 상태 변경과 같은 DB 작업에서 이력을 자동 추가하므로 별도 이력 쓰기를 누락할 수 없다. 철회는 행 삭제 대신 상태 갱신으로 기록하며, 일반 동의 변경에서는 이력을 수정하거나 덮어쓰지 않는다. 이력 조회는 `recorded_at`, 동일 시각에는 `id` 순서를 사용한다. 개인정보 삭제 요청에 따른 이력의 보관·삭제 범위는 아래 운영 정책과 함께 확정한다.

보관기간은 임의로 숫자를 정하지 않는다. 학교 정책·성적 이의 신청 기간 등과 함께 별도 확정. 삭제 요청은 Slack 원본과 TeamPlanet 사본의 차이를 구분하여 안내한다. 삭제되거나 동의 철회된 데이터가 기존 분석 초안에 남아 있는 경우의 폐기·재분석 절차를 설계한다.

## 보안

OAuth 토큰 암호화/비밀 저장, 전송 TLS, 접근 로그, 최소권한, 작업/분석 결과 버전, API 호출/데이터 열람 감사로그, 외부 모델에 필요 이상 개인정보 전달 금지.
