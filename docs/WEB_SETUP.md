# 교수 설정 마법사 — #9 작업 초안

## 선행 PR과 검토 범위

`codex/9-slack-setup-wizard`는 최신 origin/main에서 생성한 뒤, 요청된 PR 기준 개발을 위해 #36(로그인)과 #39(인증·권한·Slack·동의의 누적 브랜치)를 로컬 작업 브랜치에 포함했다. main에는 병합하지 않았다. 선행 PR #34 → #35 → #37 → #38 → #39와 로그인 #36이 먼저 검토·병합되어야 한다. 그 전에는 main 대상 diff에 선행 변경도 포함되므로 이 PR을 먼저 병합하지 않는다. #9 자체 변경은 웹 설정 화면, 수업 선택 역량 API·공유 계약·DB 테이블과 migration 0010 및 테스트다.

## 구현된 동작

- 로그인 확인 뒤 `/workspace`에서 OAuth 결과별 안내와 실제 연결 상태를 구분한다. `installed` 쿼리만으로 연결 성공/수집 활성으로 판단하지 않는다.
- 수업·팀·정책 설정·학생·매핑·동의·실시간 채널 멤버십·수집 상태를 공유 schema로 검증해 조회한다. ID와 OAuth 결과만 URL에 보존하고 새로고침·재로그인 후 서버 응답에서 복원한다. 알 수 없는 쿼리와 외부 이동 URL은 버린다.
- 수업 생성, 승인 버전/종료일 설정, 공식 공개 채널 생성·지정, 학생 등록·Slack 매핑·초대·오프라인 동의 증빙 기록을 기존 API에 연결한다. 수동 초대 필요·이미 참여·초대 성공을 구별한다.
- 선택 역량은 명시적으로 1~4개 선택해 수업별 서버 설정으로 저장·복원한다. 미설정은 null이며 자동 전체 선택하지 않는다. 교수 소유권·세션·Origin 검사와 감사 기록을 적용하고 저장·감사를 같은 batch로 처리한다. 기존 run·평가·확정본·동의 이력은 변경하지 않는다. #16은 실행 시 설정을 snapshot으로 고정해야 한다.
- 동의 버전과 학생 재확인, 봇·학생 참여와 미매핑 계정, 수업 종료일을 보여준다. 실제 activate 성공 뒤에도 collection 상태를 다시 조회하며 UI 플래그로 gate를 우회하지 않는다. 조회 불가·거부·갱신 중에는 활성으로 표시하지 않는다. 상태 미확인 때도 수집 중지를 요청할 수 있다.
- 중복 쓰기를 차단하고, 요청은 15초 후 중단한다. 429의 서버 대기 시간을 적용하며 자동 재시도하지 않는다. 요청 중 페이지를 벗어난 뒤 도착한 응답은 무시한다. 세션 만료는 설정 정보를 지우고 로그인으로 돌아간다.
- 개발 fixture는 테스트에만 사용한다. 운영 코드에는 합성 성공 응답/fixture 활성화 옵션이 없다. 서류 스캔·학생 대화·토큰을 저장하지 않는다.

## 미완료 — Draft 유지 사유

- 분석 역량 저장은 연결했지만 분석 실행 자체는 #16/#21 후속 범위다. 수집 활성 상태와 역량 설정 상태, 실제 분석 실행 가능 여부를 구분한다.
- 수업 시작일·담당 교수 연락처·문의 기한은 현재 pilot API의 필드에 없다. 임의 API/DB 필드를 추가하거나 저장됐다고 표시하지 않으며 운영자 확인 안내를 제공한다.
- 학생 QR 화면과 본인 확인은 #29에서 구현해야 한다. 현재 화면은 서버의 학생 재확인 상태를 표시하지만 교수 체크만으로 재확인을 대체하지 않는다. QR 링크 전달 화면은 학생 본인 확인 경계에 맞춰 연결해야 한다.
- 실제 Slack OAuth·멤버십·동의 수집의 브라우저 통합과 외부 고지 일치는 선행 PR 병합 및 운영 계정 설정 후 #24에서 검증해야 한다. 합성 검증이 실제 서비스 설치·동의 완료를 뜻하지 않는다.
- 열린 #40/#41이 migration 0008·0009를 사용해 신규 migration을 0010으로 배정했다. 기존 SQL/트리거는 수정하지 않았다. 현재 schema snapshot은 #39 기준으로 생성했으므로 #40/#41이 먼저 병합되면 병합 전에 해당 변경을 포함해 Drizzle snapshot과 journal을 재정합해야 한다. Draft를 먼저 병합하지 않는다.

## 검증

`bun test tests/web-setup.test.ts`로 조회 복원, 학생 재확인 gate, 실제 활성화 성공/거부, 다른 팀 응답 거부, 수동 초대, 중복 요청·dispose 경합, 세션 제거, 안전한 URL 복원을 검증한다. 브라우저 검증은 API를 가로채는 합성 응답만 사용한다.

선택 역량은 `apps/api/src/course-rubric.test.ts`에서 실제 메모리 SQLite와 인증 세션으로 정상 저장/조회, 미설정 null, 타 교수/없는 수업 거부, 잘못된 선택/위조 소유자 거부, Origin/세션 검사, 감사 실패 시 롤백, 기존 run·평가·동의 이력 보존을 검증한다. 로컬 D1 `verify:upgrade`는 migration 0010 적용과 반복 적용 뒤 선택 설정 보존도 확인한다. 브라우저에서는 빈 선택 저장 거부, 두 역량만 명시 저장, 새로고침 뒤 정확히 두 항목 복원과 수집 상태/분석 실행 준비 상태의 구분을 확인했다.

수업 초기 설정은 실제 startsAt·endsAt을 저장하고 소유 교수의 이메일을 서버에서 반환해 표시합니다. 시작/종료 역전은 거부하고 과거 클라이언트의 startsAt 생략은 기존 값을 보존합니다. 문의 기한 n은 #30, 학생 개인 QR은 #29에서 연결합니다. 0008 동의 FK·0009 Events·0010 History를 보존하고 설정 migration은 미적용 상태에서 0011로 재정합했습니다.
