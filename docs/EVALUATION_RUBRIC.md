# Evaluation Rubric — communication-v1

2026-10-27 운영자가 MVP 개발 기준으로 승인했다. 교수의 사전 루브릭 승인을 개발 차단 조건으로 두지 않는다. 교수 승인·교육적 타당성 검증을 완료했다는 뜻은 아니다. 실제 결과의 교수 검토·수정·최종 확정은 유지한다. [ADR-0003](ADR/0003-rubric-model-profile.md)을 따른다.

교수는 **수업 초기 설정에서 아래 네 항목 중 1~4개를 명시적으로 선택**한다. 전체 자동 선택·빈 선택·중복·알 수 없는 key는 허용하지 않는다. 선택하지 않은 역량은 모델 입력의 평가 대상과 결과 카드·출력 리포트에서 제외한다. 역량 확장은 새 rubric 버전으로 진행한다.

| 역량 | 관찰 가능 행동 | 금지된 대리 지표 | 근거 부족일 때 |
|---|---|---|---|
| 1. 정보 전달의 명료성 | 질문의 대상/의도 명확화, 상황·제약 정리, 오해 해소 | 긴 메시지·메시지 수 | 관찰 불충분 |
| 2. 정보 공유·협업 지원 | 관련 자료 적시 공유, 요청에 실질 답변, 막힌 동료 지원 | 링크 수·답장 수 | 관찰 불충분 |
| 3. 피드백 수용·상호 조율 | 타인 의견 확인, 합리적 반론, 대안 제안, 수정 반영 | 무조건 동의·이모지 수 | 관찰 불충분 |
| 4. 의사결정·실행 연결 | 합의 내용 정리, 책임/다음 행동 명료화, 변화 상황 공유 | 회의 주도 횟수 | 관찰 불충분 |

## 출력 구조

학생별 개요와 **선택한 역량별 카드**를 제공한다. 카드는 공유 TypeScript 계약의 `judgement`, `narrative`, `evidenceIds`, `counterEvidenceIds`, `confidence`, `limitations`, `requiresHumanReview`를 사용한다. 개요로 근거 부족을 감추거나 선택하지 않은 역량을 추정하지 않는다. 단계 JSON 상세는 #16에서 확정한다.

| 판정 | 공통 앵커 |
|---|---|
| `observed_strength` 관찰된 강점 | 해당 행동을 뒷받침하는 직접 근거가 있고 관찰 범위 안에서 설명 가능 |
| `mixed` 혼재 | 지지 근거와 다른 방향의 반례가 함께 있어 한 방향으로 단정하기 어려움 |
| `needs_support` 지원 필요 | 명시적 요청·합의와 실제 관찰 행동 사이의 문제를 직접 근거로 설명 가능. 단순 침묵·기회 부재는 제외 |
| `insufficient_evidence` 관찰 불충분 | 관련 행동·역할·문맥을 충분히 확인하지 못함. 한계와 사람 검토 필요를 필수 기록 |

각 행의 관찰 행동에 이 공통 앵커를 적용한다. 예: 명료한 재현 조건은 clarity의 강점, 요청과 관련 있는 실질 설명은 information_sharing의 강점, 의견 배제 후 수정은 feedback_alignment의 혼재, 인지한 합의 절차를 생략했다는 명시적 기록은 decision_execution의 지원 필요 후보다. 메시지 수 임계치·점수·학생 간 순위는 만들지 않는다.

공유 `rubricSelectionSchema`와 `assessmentSetSchema`는 선택 버전·학생×선택 역량의 정확한 행 수·중복·미등록 근거 ID·근거 없는 부정 판단을 검사한다. 근거 ID 존재만으로 주장 의미·동의·최신성을 보장하지 않으므로 #16~#20의 서버 검증을 추가한다.

## 원칙

- 근거 없는 0점/낙제 금지. 기회를 가질 수 없었던 행동에 감점 금지.
- 활발한 발언과 유익한 발언 구분. 팀에서 맡은 역할/맥락 고려.
- 공격적 표현도 전체 대화·반응·후속 조치 없이 단편 평가 금지.
- 결측 기간, 오프라인 협업, 다른 협업 툴 사용은 제한으로 명시.
- 평가 불일치 사건은 교수 확인 대상으로 표시.
- 내용상 개인정보, 건강, 정치 성향, 사적 관계를 평가 근거로 사용하지 않음.

## 신뢰도 검증

`@teamplanet/contracts/evaluation-fixtures`에 한국어 스레드, 실질 공유, 반례, 합의 위반, 낮은 활동량/오프라인 결측, 이미지 모호성/프롬프트 주입 사례와 예상 방향·근거를 공유한다. 잘못된 근거 ID·선택 외 역량·중복·누락·근거 없는 부정 판단 출력도 포함한다. 이미지 사례는 설명 기반 합성 fixture이며 실제 이미지 인식 성능을 검증한 것은 아니다.

현재 검사는 계약/fixture 정합성 검사다. 실제 Qwen 호출의 한국어 품질·장문 누락·이미지 정확도를 통과했다고 보고하지 않는다. #25에서 품질과 편향을 기록하되 외부 교수의 루브릭 사전 승인을 MVP 개발 선행 조건으로 추가하지 않는다.
