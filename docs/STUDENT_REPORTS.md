# 학생별 출력과 교수 전달 (#31)

교수 확정 결과에서 학생 한 명의 리포트 미리보기를 연다. 학생용 평가 포털은 만들지 않는다. `/reports/print?run=<internal-id>&student=<internal-id>`의 SSR은 공개 로딩 문서만 반환하고 실제 자료는 세션·소유권 보호 API로 읽는다. URL이 알려져도 다른 교수/로그아웃/다른 실행 학생의 자료를 열 수 없다.

`GET /v1/analysis-runs/:id/reports/:studentId`는 현재 Slack 원문/이미지·요약/후보·교수 확정 hash/버전과 유효성/보관 기한을 검증한다. finalized run만 제공하고 학생별 선택 역량·교수 판단/사유·AI 초안 판정/신뢰도·근거 요약/반례·한계·교수 확인/검증 시각·버전을 구분한다. 전체 원문·Slack 링크·다른 학생의 개별 평가 배열을 반환하지 않는다. 다른 학생 이름, 연락처, 외부 링크와 원시 내부 참조의 자유 서술 포함을 줄인다. 이는 개인정보 전체 탐지 보장이 아니며 교수의 전달 전 확인을 유지한다. 학생별 한계와 실행 범위 한계만 출력하고 전원 평가가 합쳐진 C 자유 서술은 복제하지 않는다. 전체 AI/검토 이력은 교수 결과 화면에 보존된다.

인쇄 버튼은 개인정보 확인 전에는 비활성이다. `POST /:studentId/print`는 `{artifactHash,professorConfirmedAt,privacyReviewed:true,requestId}`를 받아 다시 현재 원문을 검증한다. 동일 D1 batch의 validity·finalized·확정/AI 출력 조건과 print 감사 기록이 성공해야 인쇄 데이터를 돌려준다. 미리보기 당시 검증을 재사용하지 않는다. source 변경/삭제·철회·만료·미확정/버전 충돌409, 타인/없는 학생404, 로그인401, Slack 검증 장애503이다. 장애를 삭제로 기록하지 않으며 이전 미리보기를 지운다.

print 감사는 검증된 출력 승인을 기록한다. 사용자가 대화상자를 취소했는지, 실제 종이/PDF 저장이나 학생 전달이 완료됐는지는 브라우저 밖의 동작이며 성공으로 추정하지 않는다.

개인 출력은 원래 B와 수정 B의 해당 학생 한계를 함께 보존한다. 학생 귀속이 없는 A chunk 전체 자유 서술은 B/근거 한계로 상속된 경우에도 개인 출력에서 제외하고 팀 전체 한계 생략 안내를 남긴다. 전체 상세는 교수 검토 화면에 보존한다. 미리보기를 새로 검증하면 개인정보 확인도 해제한다. 인쇄 전 이벤트만으로는 브라우저가 미리 캡처한 URL 머리글을 바꿀 수 없어, 화면 진입 시 URL의 내부 ID를 제거한다. 새로고침용 run/student 참조만 history state에 유지하며 원문/결과 본문을 저장하지 않는다. 명시적으로 잘못된 링크가 들어오면 이전 학생 참조로 돌아가지 않는다.

브라우저 네이티브 인쇄/PDF 저장은 POST 직후 한 번만 승인한다. 확인 전 Ctrl+P는 차단 안내만 출력하며 교수 워크스페이스 전체를 잘못 출력하지 않는다. URL 머리글에 내부 ID가 들어가지 않도록 인쇄 중 URL을 제거하고 이후 복원한다. 인쇄 후 승인·학생 내용을 지우고 다음 출력에는 다시 확인·검증을 요구한다. 외부 Slack과 사용자 프린터는 원자적 transaction이 아니므로 검증 시각 이후의 외부 변경/이미 전달한 종이/PDF 회수를 보장하지 않는다. 원문 변경·철회·만료 후 이전 버전 정정/재전달과 수업 종료 후 달력 3개월 정책을 출력물에 고지한다. 서버에 리포트 파일·원문을 별도 저장하지 않는다.

## #24 검증 인수인계

`tests/reports.test.ts`는 실제 SQLite와 source fence 위의 정상 finalized 출력, 미확정/타인/다른 학생/필수 개인정보 확인 누락/버전 충돌, 확정 후 원문 수정·삭제·철회/보관 만료·Slack 장애, 출력 batch 직전 철회 rollback과 session/Origin 경계를 포함한다. `tests/helpers/result.ts`는 실제 migrations·prepare·원문/epoch guard에 합성 결과를 구성하며 외부 API/실제 키 없이 사용할 수 있다. #22/#23 회귀도 함께 실행한다.

브라우저 검증은 실제 합성 API의 GET→명시 확인→POST→인쇄를 연결했다. 320px 미리보기 가로 넘침과 JS 오류가 없고, 승인 전 차단 PDF(1페이지)에는 학생 내용이 없었다. 긴 한국어·줄바꿈의 정상 PDF(4페이지)를 Chromium으로 출력하고 Poppler로 모든 페이지를 PNG 렌더링해 글리프·페이지 번호·겹침/잘림을 확인했다. pypdf 텍스트 검사로 마지막 문장, 원문·내부 ID 부재를 확인했다. PDF/PNG는 합성 QA 임시 산출물이며 저장소에 학생 자료나 리포트 파일을 커밋하지 않는다.

재현 시 합성 fixture를 사용하고 실제 키를 요구하지 않는다. PDF에는 네이티브 페이지 번호·버전/교수 확인·검증 시각이 있어야 한다. 출력 전 원문 검증 실패 시 화면과 PDF에 이전 학생 내용이 남지 않아야 한다. 실제 Slack/OpenRouter 운영·모델 품질/학교 정책 검증은 #24/#25에서 별도로 수행한다.
