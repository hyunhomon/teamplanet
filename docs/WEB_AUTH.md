# 교수 로그인 UI — #4

소개 화면의 로그인 링크와 `/login`, `/workspace`는 동일 origin의 실제 `/v1/auth/*` 계약을 사용한다. 이메일 요청 → 6자리 OTP → 쿠키 세션 확인 → 워크스페이스 → 로그아웃 흐름이다. 인증 API #2와 소유권/감사 #3은 별도 구현이며, 이 UI의 동작 확인이 해당 서버 기능의 통합 완료를 뜻하지 않는다.

## 세션과 화면 경계

- SSR HTML에는 공개 로딩 화면만 있다. `/auth/me`의 성공 응답을 공유 schema로 검증하기 전에는 계정 정보를 렌더링하지 않는다. 페이지와 인증 요청은 `no-store`를 사용한다.
- OTP 검증 성공 뒤에도 `/auth/me`를 다시 호출해 브라우저의 세션 쿠키가 실제로 적용됐는지 확인한다. OTP·세션·계정은 localStorage/sessionStorage, URL에 저장하지 않는다.
- 세션 만료 시 계정 정보를 즉시 지우고 로그인으로 돌아간다. 창으로 돌아오거나 숨겨진 탭이 다시 보이거나 뒤로 가기로 페이지가 복원되면 세션을 재확인한다. 같은 origin의 다른 탭에도 성공한 로그아웃을 알린다.
- 로그아웃 요청 중에는 워크스페이스를 숨긴다. 서버 종료가 실패하면 성공으로 표시하지 않고 다시 시도하게 한다. 중단되거나 뒤늦게 도착한 요청은 현재 화면 상태를 덮어쓰지 않는다.
- 이 화면 제어는 서버 권한 검사를 대신하지 않는다. 후속 데이터 화면/API는 세션 교수의 소유권을 서버에서 검증해야 한다. 현재 셸에는 수업·학생·평가 자료가 없으며 미구현 기능은 준비 중으로 표시한다.

## 코드 요청과 오류

공유 schema의 `expiresAt`, `resendAvailableAt`, 오류의 `retryAfterSeconds`와 `Retry-After`를 사용한다. 재전송은 서버가 정한 시각부터, 429는 명시된 기한 중 더 늦은 시각부터 가능하다. 이메일 입력으로 돌아가도 기존 대기 시간은 유지한다. 중복 클릭은 추가 요청을 만들지 않는다.

오입력·만료·메일 제공자 오류·네트워크 오류를 구분하고 재입력/재전송/재시도를 제공한다. API가 미구현인 경우 서비스 준비 안내를 표시한다. 응답 형식이 잘못됐거나 API에 연결할 수 없으면 합성 성공 응답으로 대체하지 않는다. 요청은 12초 후 중단하며 자동 재발송하지 않는다.

## 검증과 후속 통합

`bun test tests/web-auth.test.ts`는 공통 `@teamplanet/contracts/fixtures`를 테스트에서만 사용한다. 성공·실패, 쿠키 확인, 서버 대기 시간, 경합과 세션 제거를 검증한다. 운영 컴포넌트에는 fixture import나 mock 활성화 옵션이 없다.

브라우저 검증은 로컬 웹 서버에서 `/v1/auth/*` 응답을 브라우저 테스트 도구로 가로채 합성 응답을 제공한다. 고정 fixture 시각 대신 실행 시각에 맞는 만료/재전송 시각을 사용한다.

1. `/workspace` 직접 진입 시 세션 확인 전 계정이 노출되지 않는지 확인한다. 401이면 이메일 입력이 나타나고 키보드로 요청·OTP 입력·제출할 수 있어야 한다.
2. 메일 제공자 503 뒤 재요청, 앞자리 0을 포함한 오입력, 429 대기, 코드 만료 후 재전송을 확인한다.
3. 검증과 `/me`가 성공하면 워크스페이스가 나타나고 새로고침으로 세션을 복원해야 한다. 320px 화면에서 가로 넘침과 겹침 없이 읽혀야 한다.
4. 두 탭의 로그아웃, 세션 만료, 로그아웃 실패 후 재시도, 세션 확인 장애 후 재시도에서 계정 정보가 사라지는지 확인한다.
5. SSR 응답의 `Cache-Control: no-store`, 계정 정보 미포함, 브라우저 저장소 미사용과 production bundle의 fixture 미포함을 확인한다.

실제 메일 발송·쿠키·Origin 검증·다른 교수의 접근 거부를 포함한 인증/권한 API 통합 증빙은 #2/#3 병합 후 #24에서 연결한다. 실제 메일이나 학생 자료는 이 UI의 합성 검증에 사용하지 않는다.
